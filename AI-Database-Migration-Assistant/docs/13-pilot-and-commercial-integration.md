# DM pilot and commercial integration

## Pilot offer

Proposed service: assessment and migration of one agreed application/database pair, within an explicit volume/object/window scope, including rehearsal, reconciliation and handover. Begin with a supervised pilot; only advertise unattended recipe execution after qualification. Do not market 'any database', guaranteed zero downtime or guaranteed perfect AI conversion.

Intake produces a compatibility assessment and a scoped estimate. The domain owner supplies business meaning and accepts intentional exclusions. The service provides migration evidence and recovery procedures. Changes to source schema, target application or data scope trigger a reviewed revision rather than an undisclosed overage.

## Relationship to the reference project

The [WS plan](../../AI-Product-Website-Sales-and-Subscription/README.md) is a commercial/platform reference, not an existing deployed service. If adopted, WS owns product offers, checkout, subscription/entitlement and usage settlement; DM owns database access, mapping, execution and customer-data outcomes. Decide one identity and job authority during S02.

Proposed adapter fields: product_id=database-migration, authenticated workspace/principal, logical operation ID, qualified workflow/recipe version, input references, admission status, run ID, progress, report reference, review-required status and usage disposition. Commercial support sees operational metadata, not database credentials or customer records.

Billing units remain undecided: assessment, migration project or qualified repeat run are options. Define cancellation/refund/retry policies before taking payment. A worker retry must not create a second billable migration. Settle usage through the commercial ledger once per logical operation under the published policy; a UI 'success' message is not proof of delivery.

## Pilot sequence and exit

1. Select one consenting customer and actual old/new applications.
2. Agree scope, roles, downtime, data permission, success measures and recovery limits.
3. Run deterministic baseline and Astra assessment on approved copies.
4. Resolve critical semantics; complete full rehearsal and application tests.
5. Execute only after the defined production authority exists.
6. Observe agreed workflows, reconcile, hand over evidence and measure actual cost/review time.

No customer contact, payment, outbound message or production execution is part of this documentation task. Pilot evidence may show that assisted migration is commercially useful even when the model cannot meet unattended qualification. Record that result without changing the claim to conceal it.
