## Capability coverage policy

[Astra capability IDs A01-A15](11-astra-llm-feature-mapping.md) map to actual source PI/sprint sections and identify reuse, integration or qualification work. References to A14/A15 mean explicit exclusion/deferment where appropriate, not a commitment to implement paid-provider, MCP, browser or multi-agent features.

The core launch needs business modules plus the qualified subset of Astra: scoped gateway, durable execution where used, bounded extraction, reviewed retrieval, verification/abstention, runtime limits and operational evidence. PI-07 adds consented feedback and evaluated enhancement. Model training, generalized research/coding/computer agents, MoE and a new LLM implementation are not product modules.

## Change control

If a feature changes, update the sprint's scope/acceptance, its PI exit gate if affected, this matrix and the source dependency record. Attach actual evidence before changing status. The source file is a recorded snapshot; reread relevant later Astra updates before implementing a dependency.
