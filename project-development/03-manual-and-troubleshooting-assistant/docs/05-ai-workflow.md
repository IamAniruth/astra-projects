# Approved-source retrieval, answers and evaluation

Pipeline: authenticate -> establish equipment context -> select approved/applicable revisions -> permission-filter -> retrieve -> assemble evidence with prerequisites -> generate bounded answer -> check claims/citations and current source state -> show answer or abstain/escalate.

Start with exact model/fault-code matching and a lexical retrieval baseline. Benchmark qualified Astra hybrid/learned options before adopting them. Permissions and applicability constrain candidates before scoring; do not retrieve across tenants and hide unauthorized passages only after generation. Unknown serial/firmware requirements cause clarification. Manual revision date is not a substitute for explicit applicability.

Chunk by section/procedure boundaries while preserving page mapping, headings, warnings, prerequisites, numbered steps, units, negation and stop conditions. Keep cross-page and cross-section dependencies linked. OCR confidence or a valid citation alone cannot establish numerical correctness. Reject unsupported symbols/table structures; preserve the original page for expert inspection.

Procedural answers quote or closely preserve the approved procedure with its required context and step order. Never combine steps from incompatible manuals into a new procedure. Every actionable claim must be supported by an applicable passage. Source wording must not lose a mandatory qualification, isolation requirement, limit or stop condition through summarization. When the required context exceeds budget, narrow the question or show the full approved source; do not silently omit it.

Document instructions remain untrusted data and cannot override system behavior, invoke tools or approve a manual. Validate citation IDs, spans, hashes and permissions deterministically; assess whether cited text actually supports the claim separately. A citation resolver can prove a page exists, not that an answer is safe or correct. Contradictory approved sources trigger an explicit conflict and expert review unless a documented precedence rule resolves applicability.

Troubleshooting initially follows explicitly approved decision branches. User observations select branches; the model cannot invent missing measurements, prerequisites or repair steps. Record unknown observations, pause at stop conditions and route unresolved cases to a named role. Expert replies stay separate from published source knowledge until document approval. No equipment actuation is part of this product.

Evaluation uses permitted manuals plus synthetic adversarial cases. Split by procedure/manual version or equipment variant to prevent near-duplicate leakage. Include wrong model, overlapping serial ranges, outdated/withdrawn revisions, conflicting manuals, no-answer questions, diagrams, poor scans, cross-page procedures, missing prerequisites, prompt injection, revoked access and follow-up questions after an asset switch.

Before running, a domain reviewer registers numeric thresholds, sample minimums and critical-failure rules. Measure retrieval recall@k, answer support/accuracy, citation correctness, applicability correctness, mandatory-context retention, correct abstention/escalation, answer coverage, time to locate information, latency and cost. Report denominators and breakdown by equipment/input class. Lower unanswered rate alone is not success. Any critical unsupported procedural instruction or access leak in the release evaluation blocks release pending remediation and re-evaluation. No thresholds or measured results are claimed yet.
