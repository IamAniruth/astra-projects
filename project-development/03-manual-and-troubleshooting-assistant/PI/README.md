# Manual and troubleshooting roadmap

All work is Planned. PI means Program Increment. Three sprints per PI follow the other project plans. This organizes scope, not a delivery commitment. If two-week sprints are chosen, six core PIs imply 36 nominal weeks plus six optional weeks. Re-estimate after discovery/feasibility using actual staffing and corpus quality.

| PI | Outcome | Sprints |
|---|---|---|
| [PI-01](PI-01-foundation/README.md) | Investigation and secure foundation | S01-S03 |
| [PI-02](PI-02-approved-knowledge/README.md) | Approved manuals and indexing | S04-S06 |
| [PI-03](PI-03-grounded-assistance/README.md) | Retrieval, cited answers and troubleshooting | S07-S09 |
| [PI-04](PI-04-review-lifecycle/README.md) | Expert review, technician workflow and revisions | S10-S12 |
| [PI-05](PI-05-commercial-readiness/README.md) | Commercial, scope and operational readiness | S13-S15 |
| [PI-06](PI-06-pilot-launch/README.md) | Independent evaluation and launch | S16-S18 |
| [PI-07](PI-07-controlled-improvement/README.md) | Optional governed improvement | S19-S21 |

S01 is the go/narrow/stop decision; S02 is technical feasibility. S08 can demonstrate bounded cited answers on qualified fixtures; S12 completes the internal source-lifecycle workflow. S16 independently evaluates release quality; S17 measures an assisted pilot; S18 is the conditional launch gate. PI-07 is optional.

An internal demo need not include subscriptions. Paid pilots still require applicable operational/commercial readiness. Search-only fallback is separately labelled and cannot pass acceptance for synthesized answers. A failed equipment/source qualification narrows the supported matrix rather than being averaged into an overall score.
